# Непрерывное обучение малой языковой модели «как у человека»

Главный результат проекта — **готовая малая модель, которая учится непрерывно**. Это Qwen2.5-0.5B-Instruct с LoRA, которая учится порциями от простого к сложному: повторяет старое (replay), учится на «удивлении» и периодически «спит». Её можно запустить, дообучать новыми данными и в чате, сохранять и продолжать с того же места, а также выгрузить как обычную модель Hugging Face.

**Итоговая модель лежит на Hugging Face: [makltd1/continual-lm](https://huggingface.co/makltd1/continual-lm)** (обычная модель `transformers`, лицензия Apache-2.0).

Контрольные эксперименты E0–E6 проверяют, какие приёмы реально уменьшают забывание (гипотезы H1–H4). Обзор литературы — [reports/research.md](reports/research.md).

Это исследовательский проект, а не продукт: малая модель, учебные задачи только на английском, итоговая модель обучена один раз.

## Результаты

Подробно — [reports/conclusions.md](reports/conclusions.md), таблицы и графики — [reports/summary.md](reports/summary.md). 29 прогонов на Kaggle, три seed на конфигурацию. Сырые журналы прогонов (`runs/`) в этом репозитории не опубликованы; отчёты собраны из них.

| Гипотеза | Вывод |
|---|---|
| H1: replay снижает забывание | **Подтверждена** для историй (забыто 11% против 28%) и вопросов по тексту (5% против 19%); по арифметике — данных недостаточно |
| H2: учёба на «удивлении» — то же качество за меньшее число шагов | **Частично**: на 31% меньше шагов, качество то же на задачах с коротким ответом, чуть хуже на текстах; по времени не быстрее |
| H3: «от простого к сложному» ускоряет освоение | **Не подтверждена**: медленнее (137 шагов до цели против 78) |
| H4: «сон» удерживает старые задачи | **Данных недостаточно**: эффекта не видно |

Следование инструкциям (задача 0) обучение на узких задачах портит всегда: остаётся 81–88% от исходной модели. Лечит это повтор собственных ответов модели на общие запросы (self-replay): с ним 94–95%.

**Итоговая модель — E5_final_v2**: все приёмы плюс повтор 2000 собственных ответов. Задача 0 — 95% от исходной модели, критерий ТЗ (≥ 90%) выполнен. На своих задачах она лучше исходной: вопросы по тексту — 0,60 против 0,37, арифметика — 0,80 против 0,41. Perplexity на общем тексте выросла на ~7%.

### Как скачать и запустить

Модель опубликована как обычная модель Hugging Face, код проекта для её запуска не нужен:

```python
from transformers import AutoModelForCausalLM, AutoTokenizer

tok = AutoTokenizer.from_pretrained("makltd1/continual-lm")
model = AutoModelForCausalLM.from_pretrained("makltd1/continual-lm")
messages = [{"role": "user", "content": "What is 17 + 25? Reply with the answer only."}]
inputs = tok.apply_chat_template(messages, add_generation_prompt=True, return_tensors="pt", return_dict=True)
out = model.generate(**inputs, max_new_tokens=64, do_sample=False)
print(tok.decode(out[0, inputs["input_ids"].shape[1]:], skip_special_tokens=True))
```

Работает и на CPU: ответ занимает от нескольких секунд до полминуты.

Чтобы учить модель дальше, `chat.py` и `live.py` нужно **состояние ученика** (адаптеры, буфер повтора, счётчики). Состояние итоговой модели (контрольная точка `ckpt-000020`, около 105 МБ) лежит в папке `state/` того же репозитория на Hugging Face:

```bash
pip install huggingface_hub
python -c "from huggingface_hub import snapshot_download; snapshot_download('makltd1/continual-lm', allow_patterns='state/*', local_dir='download')"
```

Базовая модель Qwen2.5-0.5B-Instruct и закреплённые наборы данных скачиваются при первом запуске. Дальше:

1. Чат с дообучением на ваших исправлениях: `python chat.py --state download/state`. Если оперативной памяти мало (8 ГБ), добавьте `--low-memory`: модель займёт вдвое меньше. Каждое сообщение пишите в одну строку.
2. Учить её дальше своими данными: `python live.py --state download/state --inbox inbox`.

Обе команды пишут в папку состояния, поэтому скопируйте её заранее, если нужен оригинал. Буфер повтора в `state/` содержит фрагменты обучающих наборов (по 640 примеров на задачу) под их собственными лицензиями, они перечислены на [странице модели](https://huggingface.co/makltd1/continual-lm). В командах ниже `states/ewai-e5` — просто пример папки состояния, подойдёт любая.

## Итоговая модель (E5)

Итоговая модель — конфигурация E5 (все приёмы вместе) на полном объёме из ТЗ: [configs/final/E5_final.yaml](configs/final/E5_final.yaml). Её обучает сам непрерывный режим:

```bash
# Обучение на потоке задач A→B→C→D; после остановки продолжает с последней порции
python live.py --config configs/final/E5_final.yaml --state states/ewai-e5 --stream builtin \
               --export exported/ewai-e5
```

| Что нужно | Как |
|---|---|
| Запустить без кода проекта (FR-15) | `exported/ewai-e5` — обычная модель Hugging Face; пример в её `README.md`. Выгрузить из любого состояния: `python export.py --state states/ewai-e5 --out exported/ewai-e5` |
| Продолжать учить новыми данными (FR-13) | `python live.py --state states/ewai-e5 --inbox inbox`. Кладите в папку `inbox/` файлы `.jsonl`, по примеру на строку: `{"prompt": "запрос", "response": "нужный ответ"}`. Каждые `live.portion_size` примеров (по умолчанию 32) — порция: отбор, replay, обучение, сон по расписанию |
| Чат с обучением на обратной связи (FR-16) | `python chat.py --state states/ewai-e5`. После ответа модели: `/good` — ответ хороший, учиться на нём; `/fix <правильный ответ>` — учиться на правильном ответе, плюс пара «плохой → хороший» для DPO. Обучение — каждые 8 оценок или по `/learn` |
| Сохранить и продолжить (FR-14) | После каждой порции состояние пишется в папку состояния: адаптеры, буфер, счётчики, случайность. Повторный запуск той же команды продолжает с того же места. В чате — `/save`, `/quit` |
| Контрольные точки и откат (FR-17) | `python live.py --state states/ewai-e5 --list` и `--rollback ckpt-000012`. Хранятся последние 3 (`checkpoint.keep`) |

Критерий приёмки из ТЗ: следование инструкциям (задача 0) у итоговой модели — не ниже 90% от исходной Instruct-модели (`eval.retention_min`). Отчёт проверяет его автоматически.

**Повтор общих инструкций.** Первый же прогон E0 потерял ~18% следования инструкциям: модель привыкает к узким задачам. Replay в E1–E5 повторяет только задачи A–D, поэтому итоговая модель дополнительно повторяет собственные ответы исходной модели на 300 общих запросов. Запросы взяты из набора Dolly, написаны людьми и не совпадают с тестом задачи 0. Это «самостоятельно сгенерированный replay» из ресерча (источник №3). В конфиге это `self_replay`; его вклад измеряет контрольный прогон `configs/extra/E5_selfreplay.yaml`.

Чего ждать: это маленькая модель, дообученная на четырёх узких задачах. Она пишет короткие истории, отвечает на вопросы по тексту, решает простую арифметику, пишет аннотации статей по ML и следует простым инструкциям. Как большая модель она общаться не будет. Ответ в чате даётся на одно сообщение, без памяти предыдущих: так же устроены обучающие примеры.

## Эксперименты E0–E6

| Конфигурация | Что включено | Проверяет |
|---|---|---|
| E0 | Последовательное дообучение без защиты | Базовая линия забывания |
| E1 | E0 + replay (30%) | H1: replay снижает забывание |
| E2 | E1 + отбор по «удивлению» | H2: то же качество за меньшее число шагов |
| E3 | E1 + curriculum | H3: «от простого к сложному» ускоряет освоение |
| E4 | E1 + фаза «сна» | H4: сон удерживает старые задачи |
| E5 | Все приёмы вместе | Суммарный эффект (итоговая модель — то же на полном объёме) |
| E6 | Совместное обучение на всех задачах сразу | Верхняя граница качества |

Каждая конфигурация — отдельное обучение с нуля от исходной модели, на трёх seed.

**Задачи.** Все задачи — диалоги в chat-шаблоне модели: запрос пользователя и ответ ассистента. Потери считаются только по ответу.

- **A** — «Write a short story for young children that uses the words …» → история из TinyStories.
- **B** — вопрос по абзацу (SQuAD) → короткий ответ.
- **C** — арифметика и логика (генератор) → ответ.
- **D** — «Write the abstract of a machine learning research paper titled …» → аннотация (arXiv).

У A–D по 5000 примеров для обучения, по 625 для валидации и теста. Ещё две задачи только замеряются и никогда не обучаются:

- **T0** — задача 0, следование инструкциям: 152 инструкции 17 типов с автоматической проверкой условий (формат, длина, язык, ключевые слова). Устроена в духе IFEval, но короче.
- **G** — общий тест языка, perplexity на WikiText-2.

**Контрольная база.** До любого обучения замеряется сама Instruct-модель. Отчёт показывает отличие каждой конфигурации от этой базы.

**Урезанный объём.** Он подогнан под бесплатные GPU, как разрешает таблица рисков ТЗ («меньшие порции»):
- порция — 500 примеров вместо 1000, по 5 порций на задачу;
- после каждой порции — проверка на 200 примерах вместо 300.

Итоговая модель обучается на полном объёме. Полный объём для экспериментов: `--preset configs/presets/full_tz.yaml` с отдельной папкой результатов.

## Как запустить

### На GPU (нужно 16 ГБ)

Эксперименты проекта считались на двух видеокартах T4 в Kaggle (около 30 GPU-часов в неделю). На любой машине с GPU на 16 ГБ всё работает так же: поставьте зависимости, как в разделе «Локально» ниже, и используйте команды из раздела «Команды». Скрипты пропускают завершённые прогоны (те, где есть `final.json`), поэтому остановленное задание можно запустить той же командой ещё раз. Ноутбуки, которые использовались для Kaggle и Colab, в этот репозиторий не входят.

### Локально

```bash
python -m venv .venv
.venv\Scripts\activate          # Linux/macOS: source .venv/bin/activate
pip install torch               # для GPU — сборку под свою CUDA с pytorch.org
pip install -r requirements.txt
```

На CPU удобно запускать чат и выгрузку. Обучение тоже работает, но медленно.

## Команды

```bash
python run.py --all                               # все эксперименты E0–E6, по 3 seed
python run.py configs/E1.yaml --seeds 0           # один эксперимент, выбранные seed
python run.py configs/E5.yaml --preset configs/presets/smoke.yaml --seeds 0   # проверка за минуты на CPU
python report.py                                  # отчёт: таблицы, графики, выводы по H1–H4 и критерию E5
python live.py --state DIR ...                    # непрерывный режим (см. выше)
python chat.py --state DIR                        # чат
python export.py --state DIR --out DIR            # выгрузка модели
python -m pytest tests                            # тесты
```

Полезные опции:
- `--set key=value` меняет любой параметр без правки файла;
- `--force` перезапускает завершённый прогон;
- готовые прогоны (где есть `final.json`) пропускаются.

Дополнительные конфигурации в `configs/extra/`:
- `E5_dpo.yaml` — DPO на задаче C по проверке ответа скриптом (FR-11);
- `E0_full.yaml` — полное дообучение вместо LoRA.

## Как устроен цикл

Один ученик ([src/train_loop.py](src/train_loop.py)) — это модель с буфером, счётчиками и состоянием случайности. Каждая порция проходит пять шагов:

1. **Приём порции.** Если включён curriculum, задача заранее отсортирована от простого к сложному. Сложность — потеря исходной модели ([src/curriculum.py](src/curriculum.py)).
2. **«Удивление».** Отбрасываются 30% самых лёгких примеров и 2% с самой высокой потерей: такие чаще оказываются шумом ([src/surprise.py](src/surprise.py)). Образцы отброшенного и оставленного пишутся в `surprise_samples.jsonl` для ручной проверки.
3. **Replay.** Буфер добавляет 30% примеров прошлых задач ([src/buffer.py](src/buffer.py)): у каждой задачи равная квота, внутри задачи хранится случайная выборка (reservoir), чаще повторяются примеры с высокой потерей.
4. **Обновление.** Шаги обучения LoRA (r=16, lr 1e-4), при необходимости — DPO ([src/dpo.py](src/dpo.py)).
5. **Замер.** Все задачи, задача 0 и общий тест. Текущая задача дополнительно замеряется каждые 20 шагов ([src/eval.py](src/eval.py)).

**Сон** (каждые 10 порций, [src/sleep.py](src/sleep.py)):
1. Повторение примеров из буфера.
2. Слияние адаптера с весами и новый адаптер.
3. Замер до и после. Если выученные задачи или задача 0 просели больше чем на 2%, сон откатывается.
4. Чистка буфера по потере и разнообразию.

**Состояние** ([src/state.py](src/state.py)) — это адаптеры, слитые во время снов (по ~35 МБ), текущий адаптер, буфер, счётчики и состояние генераторов случайных чисел. Сама модель не копируется: она скачивается по закреплённой ревизии, и адаптеры вливаются в неё заново. Тест проверяет, что прогон с аварийной остановкой и перезапуском даёт тот же результат, что и прогон без остановки.

## Метрики

- **Качество по задаче:** EM для B и C, perplexity для A, D и G, доля выполненных инструкций для T0.
- **Отличие от контрольной базы:** конец потока минус исходная модель, по каждой задаче.
- **Забывание** (Chaudhry et al., 2018) — лучшее качество на задаче минус качество в конце. Для сравнения по A–C — *нормированное*: доля утраченного прироста. Если прирост меньше 0,01, доля не считается: это был бы шум, делённый на шум.
- **Сохранение задачи 0** — конец / база и худшее значение за поток / база. Критерий для E5 — не ниже 90%.
- **BWT / FWT** (Lopez-Paz & Ranzato, 2017).
- **Шаги до целевого качества** — 90% прироста, который E1 набирает на задаче.
- **Качество после первой порции** — эффективность по данным.
- **Стоимость** — шаги, время, пиковая память GPU.

Значимость — по правилу ТЗ: интервалы «среднее ± стандартное отклонение» по seed не пересекаются.

## Воспроизводимость

- Модель и все наборы данных закреплены по ревизии на Hugging Face в `configs/base.yaml`.
- Пулы и разбиение 80/10/10 зависят только от `data.seed` и кэшируются в `data/cache/`. Ключ кэша включает код загрузчиков.
- Seed прогона задаёт инициализацию LoRA, перемешивание и выбор примеров для replay.
- На GPU возможны мелкие расхождения из-за недетерминированных ядер CUDA. Поэтому каждая конфигурация идёт на трёх seed.

## Ресурсы

Один GPU на 16 ГБ. Веса хранятся в fp32, расчёты идут через autocast (bf16 или fp16). На T4 выходит примерно 4–5 минут на порцию и 1,5 часа на прогон E0. Все запуски Kaggle — около 25–30 GPU-часов. Точное время и память пишутся в журнал.

## Решения, принятые при реализации

- **Chat-шаблон Qwen** добавляет системное сообщение по умолчанию. Оно используется везде одинаково: в обучении, замерах, чате и у выгруженной модели.
- **Задача 0 — свой набор, а не IFEval.** IFEval — ~500 запросов, многие с длинными ответами. Это слишком дорого для замера после каждой порции и слишком сложно для модели 0,5B. Проверка — строгая: ответ засчитывается, только если выполнены все условия. Ответы генерируются жадно, с `repetition_penalty` 1,1 из настроек самой модели.
- **Точное совпадение для B и C** считается без генерации: все токены ответа должны быть самыми вероятными при правильном префиксе. Это то же, что EM жадной генерации (это проверяет тест), но в разы дешевле.
- **Забывание** считается по валидационной выборке, итоговое качество — по тестовой. Максимум по многим замерам слегка завышает забывание, поэтому в отчёте есть и BWT.
- **Replay** повторяет только прошлые задачи. Примеры из непрерывного режима и чата идут как задача `U` со своей квотой в буфере.
- **Оптимизатор** создаётся заново на каждой порции: после сна адаптер новый.
- **DPO** реализован внутри цикла формулой из TRL/Rafailov et al. `DPOTrainer` рассчитан на отдельный запуск обучения.
- **У E4 и E5 больше шагов обучения**, чем у E1: сон добавляет шаги на буфере. Это важно при интерпретации H4.
- **Буфер свой.** В Avalanche поддержка моделей Hugging Face не найдена; буфер взял оттуда идеи reservoir и квот по задачам.
