## Ответы на вопросы ресерча

1. **Методы для моделей до 1B.** Прямо на ≤ 1B проверены: replay при дообучении 405M (№1) и 205M (№3), где replay, в том числе сгенерированный самой моделью, почти устраняет забывание. LoRA на малых моделях не гарантирует меньшего забывания (№3 против №2). Слияние адаптеров с весами работает вместе с replay (№19, №20). Регуляризация KL — лучшая в №3, но в объём проекта не входит.
2. **Метрики.** Основная — **забывание по Chaudhry (№7)**: f_j = max по прошлым замерам − качество в конце, среднее по задачам A–C. Дополнительно — ACC, BWT, FWT по GEM (№6) по матрице R с замером после каждой порции. Задачи имеют разные шкалы (точность и perplexity), поэтому к сырому забыванию добавляется нормированное: доля утраченного прироста относительно исходной модели (это наше решение, источника нет). Общий тест языка — perplexity на WikiText-2 (идея из №8).
3. **Готовые реализации.** PEFT — LoRA и слияние; TRL — DPO. Буфер из Avalanche не берём: его буферы работают внутри стратегий Avalanche, поддержка HF-моделей не найдена. Пишем небольшой буфер с идеями оттуда же (reservoir + квоты по задачам, как m = M/T в GEM). DPOTrainer рассчитан на отдельный запуск обучения, поэтому несколько DPO-шагов внутри порции реализуем той же формулой потерь, что в документации TRL.
4. **Curriculum и BabyLM.** Базовая работа (№11) обещает выигрыш, но BabyLM 2023 (№9) показал, что попытки curriculum были «largely unsuccessful». Ожидание по H3 — слабый эффект или его отсутствие.
5. **Отбор по ошибке.** Высокая потеря часто означает шум (№12, №13). Поэтому порог задаётся с двух сторон: отбрасываются и слишком лёгкие, и самые «трудные» примеры (верхний хвост распределения потерь). Плюс сохраняется выборка отброшенных и оставленных примеров для ручной проверки.

## Что изменено в плане после ресерча

- **Метрики** уточнены: основная — средняя мера забывания по Chaudhry по задачам A–C (сырая и нормированная); дополнительно ACC, BWT, FWT, шаги до целевого качества, эффективность по данным, стоимость. Добавлен общий тест языка (WikiText-2).
- **Отбор по «удивлению»** — порог по квантилям потери снизу (по умолчанию 0,3) и сверху (0,98) вместо одного нижнего порога; отобранные и отброшенные примеры пишутся в журнал для ручной проверки.
- **Ожидание по H3** снижено: эффект curriculum может не превысить разброс seed — тогда вывод «не подтверждена / данных недостаточно».
- **E0 с LoRA** может забывать сильно (№3) — это нормально для базовой линии. В конфиг добавлен флаг полного дообучения для контрольного прогона.
- **DPO (FR-11)** — своя короткая реализация формулы потерь DPO внутри цикла, а не DPOTrainer.
- Конфигурации E0–E6 не меняются.

## Дополнение после нового ТЗ (Instruct-модель и готовая модель)

- **Базовая модель — Qwen2.5-0.5B-Instruct**, все задачи A–D оформлены как диалоги в её chat-шаблоне, потери — только по ответу ассистента.
- **Задача 0 — следование инструкциям.** 152 инструкции 17 типов в стиле IFEval (№22) с автоматической проверкой. Проверка на 40 инструкциях: исходная модель выполнила 50%. Провалы — настоящие ошибки модели (запрещённое слово, лишние слова, неверный перевод), а не придирки проверки. Значит, у метрики есть запас и вниз, и вверх.
- **Ожидание.** На узких данных умение следовать инструкциям портится первым (так и сказано в ТЗ; ср. падение общих навыков в TRACE, №8). Поэтому задача 0 входит в проверку отката после «сна».
- **Подтвердилось на первом прогоне** (E0, seed 0, Kaggle T4). Задача 0 упала до 82% от базы, в худший момент до 75% — ниже порога 90%. Ломаются инструкции про формат ответа (списки, абзацы, кавычки, заголовок). Решение для итоговой модели: «самостоятельно сгенерированный replay» по №3. Исходная модель отвечает на 300 общих запросов из набора Dolly (`databricks/databricks-dolly-15k`, CC BY-SA 3.0; запросы написаны людьми и не пересекаются с тестом задачи 0), и её ответы повторяются вместе со старыми задачами. Его вклад измеряет контроль `E5_selfreplay`.

## Возможные следующие шаги (вне объёма проекта)

- Replay из примеров, сгенерированных самой моделью, вместо хранения старых данных (№3, №18).
- Полный RHO-LOSS: отдельная малая модель на отложенных данных для оценки «неустранимой» потери (№12).
- MIR — выбор примеров replay по ожидаемой интерференции (№15).
- KL-регуляризация к исходной модели (№3).
- Интерполяция адаптеров вместо полного слияния (I-LoRA, №21); абляция по рангу LoRA (№19).
- Адаптивное расписание replay по оценке «силы памяти» каждого примера (MSSR, Lu et al., 2026, [arXiv:2603.09892](https://arxiv.org/abs/2603.09892): «consistently outperforms state-of-the-art replay baselines» на 11 последовательных задачах).
